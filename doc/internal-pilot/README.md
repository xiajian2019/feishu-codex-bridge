# 公司内部介绍资料：Feishu Codex Bridge

> 用于和公司同事做小范围场景介绍与兴趣验证。它是个人维护的自托管项目，不是飞书或 OpenAI 的官方产品，也不是托管云服务。

## 一句话介绍

**从手机接着用 Mac 上正在运行的 Codex。**

Codex 仍在自己的 Mac 上执行；Bridge 提供手机浏览器入口，让我查看已有 tmux 会话、发送后续提示，并在需要时通过飞书提交任务。

## 先展示的场景

MacBook 上有一个正在工作的 Codex 会话。人暂时离开电脑后，用 iPhone Safari 打开已配对的 Tmux Dashboard，查看会话输出、追加一条提示，并查看该 session 工作目录中的文件。

我已经在自己的 MacBook 和 iPhone 使用这条流程一段时间，满足了自己的主要需要。第一轮内部演示是验证同事是否也有这个场景，不代表对所有设备、网络和公司策略的兼容承诺。

## 两条入口，分开理解

- **手机接续 tmux 会话：** Safari → Bridge → Mac 上已有的 tmux session → 其中运行的 Codex。Composer 把消息交给所选 Codex session；它不是可输入任意 shell 命令的远程终端。
- **飞书提交任务：** 飞书消息进入已配置的 Direct 运行时，由 Codex SDK 执行并更新飞书任务卡片。这是另一条任务流程，可在同事对飞书入口感兴趣时单独演示。

第一场建议只讲手机接续会话这一个场景。项目还支持 Codex History、Web Task Desk，以及可选的 AAMP + Relay；先不把这些入口都塞进同一段介绍。

## 演示需要什么

- 一台运行 Bridge 和 Codex 的 MacBook；演示 session 使用单独的 tmux 会话和无敏感数据的示例项目。
- 一台已配对的 iPhone，在演示网络中可以访问 Bridge。
- Bridge 服务和 Codex session 在演示期间保持运行。
- 提前验证网络与配对状态。不要在投影或录屏中展示配对二维码、内部 IP、账号用量、个人路径或真实任务内容。

## 希望验证的问题

1. 你平时会不会在 Codex 运行期间离开 MacBook？
2. 离开电脑时，你最想从手机做什么：看进度、补充提示、检查文件，还是发起新任务？
3. 如果要在自己的 Mac 上运行，你最担心安装、网络、权限还是维护？
4. 你愿不愿意参加一次 15 分钟试用，之后用一周再反馈？
