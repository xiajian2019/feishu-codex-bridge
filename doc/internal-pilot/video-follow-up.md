# 后续视频补充计划

第一轮先做现场演示和兴趣验证，不必先制作视频。若几位同事都对同一场景感兴趣，再把现场演示拆成短视频和操作说明。

## 先留好可复用素材

现场演示时使用示例项目和演示账号。征得相关同事同意后再录屏；不要录到真实任务、内部代码、账号用量、配对二维码、内部地址或通知内容。

分别录制以下片段，之后可以重排：

1. MacBook 上 Codex 在 tmux session 中运行。
2. iPhone Safari 打开 Tmux Dashboard 并看到该 session。
3. 在 iPhone Composer 发送提示并查看返回。
4. 打开 session 文件页预览示例文件。
5. 展示手机、Bridge、tmux、Codex 之间的架构图。
6. 说明 Mac/Bridge 在线、配对认证和“不是任意 Shell”这几个边界。

每段保留几秒静止画面，方便剪辑和加字幕；桌面与手机屏幕分别录制，避免一段画面中文字过小。

## 建议的视频顺序

- **内部预热视频，60–90 秒：** 一个痛点、一条手机演示流程、一个试用邀请。
- **功能演示，4–6 分钟：** 完整展示查看输出、追加提示和查看文件。
- **部署说明，等有人要试装后再做：** 按实际配置演示安装、配对和网络要求；每一步先在干净的测试环境重走一遍。

不要把视频做成全部功能的巡览。第一条视频只回答：“我离开 MacBook 后，怎样从 iPhone 接着处理正在运行的 Codex session？”

## 从现场演示到视频的步骤

1. 先完成几场 7 分钟现场演示，整理同事最常问的 3 个问题。
2. 用其中最常见的问题做开场，保留一条核心流程，其余功能放到后续视频。
3. 录一版干净的 Mac 屏幕、一版 iPhone 屏幕和一段旁白；剪掉等待时间，给点击位置加字幕或放大提示。
4. 请一位没参与开发的同事观看，确认他能说出：Codex 跑在哪里、手机能做什么、使用需要哪些前置条件。
5. 复核遮挡和技术表述后，再决定是否扩大发布范围。

## 60 秒脚本骨架

- **0–8 秒：** “Codex 在 MacBook 上跑着，我暂时离开电脑时，怎么查看进度、补充一句？”
- **8–35 秒：** iPhone 打开已配对页面，选 session，查看输出，发送一条提示。
- **35–48 秒：** 展示 Codex 仍在 Mac 上执行；说明 Composer 不是远程 Shell。
- **48–60 秒：** “我在找几位也用 Codex、MacBook 和 iPhone 的同事试用。你会在哪种场景用它？”
