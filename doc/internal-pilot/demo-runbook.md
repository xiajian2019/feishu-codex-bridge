# 现场演示讲稿

建议控制在 7 分钟以内。开场讲一个离开电脑的实际场景，随后只演示 iPhone 接续一个 Codex session。

## 演示前预检

- 准备一个独立的 tmux session 和示例项目；Codex 已启动并停在可继续交互的状态。
- 示例任务只读、无敏感数据，例如：“请阅读 README，列出启动步骤，不要修改文件。”
- MacBook、Bridge、iPhone 已在演示网络中连通；iPhone 已完成配对。
- 先在 iPhone 上打开 Dashboard 并选中演示 session，确认输出可见、Composer 可用。
- 准备两张去敏截图作为故障备用。不要依赖现场临时扫码、临时登录或临时创建 Codex session。
- 关闭桌面通知预览，并检查投影画面、浏览器地址栏、session 名称和文件内容。

## 讲解顺序

| 时间 | 演示 | 讲解 |
| --- | --- | --- |
| 0:00–0:45 | 展示 MacBook 上已有的 Codex session | “Codex 还在我的 Mac 上运行；我想离开工位时查看进度，必要时补一句提示。” |
| 0:45–1:30 | 在 iPhone Safari 打开已配对的 Tmux Dashboard | 说明手机访问的是自己的 Bridge，不是远程桌面或云端 Codex。 |
| 1:30–2:30 | 选中演示 session，观察现有输出 | 说明 Dashboard 连接的是 Bridge 主机的 tmux session。 |
| 2:30–4:00 | 用 Composer 发送只读提示，展示 Codex 回复 | 明确这是发消息给选中的 Codex session，不是输入任意 shell 命令。 |
| 4:00–4:45 | 打开 session 文件页，预览示例 README | 说明文件范围由服务端绑定到该 session 的工作目录。 |
| 4:45–5:45 | 展示架构图和配对边界 | Mac 和 Bridge 需保持运行；手机需要能访问 Bridge，并使用配对认证。 |
| 5:45–7:00 | 邀请同事反馈 | 询问他们会在哪个时刻使用，以及是否愿意参加小范围试用。 |

飞书 Direct 可以作为第二场演示：在飞书发送一条无敏感信息的测试任务，展示任务进入 Codex 和飞书卡片更新。只有当前 Direct 运行时已预先配置并通过检查时才展示；不要把这条链路和 tmux Composer 说成同一任务流程。

## 观察记录

每次介绍后记录匿名或汇总反馈，不把同事的真实任务内容、账号信息或个人顾虑写入仓库：

- 当前是否使用 Codex、MacBook、iPhone 和 tmux。
- 哪一步最有吸引力；哪一步看起来多余。
- 最担心的安装、网络、权限或安全问题。
- 是否愿意试装；如果不愿意，具体阻碍是什么。
- 试用一周后是否继续使用，以及使用了哪个场景。
