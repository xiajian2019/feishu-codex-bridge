# 移动端第一批能力增强

范围：系统分享传入、原生本地通知/待处理中心、安全直达及工作页恢复。保持原有任务、History、Tmux、预览/复制/导出和管理入口，不包含清理、依赖精简、部署或发布。

用户已确认：先实现本机原生通知与待处理中心，锁屏/后台/退出后的即时推送明确待配置。本批不接 APNs、FCM、HMS 或第三方推送，不额外启动 Feishu Bot 消费者。

## 1. 系统分享收件箱

- Android 在原 Activity 增加 SEND / SEND_MULTIPLE；文字、URL、图片和文件先写入 App 私有 `files/mobile-share-inbox`。文件用 64 KiB 缓冲复制，不上传、不发起任务，不新增文件大小或数量硬上限。
- 收件箱在未连接后端时仍可读取。收到分享只显示顶部提示，不自动离开用户正在编辑的页面。导航新增“分享收件箱”，内容不因提示消失而丢失。
- 用户明确选择当前环境的已启用项目、现有 Tmux 或最近 20 条 History 后，追加到目标草稿；不调用任务创建、发送或审批接口。History 列表不是全量搜索。
- 原有文字草稿保留。Tmux/History 附件使用现有作用域存储，写入后读取校验；新任务复用原附件暂存接口，确认提交后才创建任务。关闭/刷新新任务的暂存附件仍沿用原生命周期，分享原件继续留在本机，可从收件箱再次导入。
- 目标的环境和设备作用域绑定到读取目标的时点；异步结果、文件读取或附件上传后再次核对。切换环境不把旧目标解释为新服务器的同名 ID。
- Task/History 沿用已有的 10 个附件、每个 25 MiB 限制；不在分享收件箱新增限制，不静默截断内容，不能导入时保留原件并提示其他目标。现有文本长度限制同样明确报告。
- 仅接受系统授权的 content URI；对外暴露的 getFile 只能读取已登记分享 ID 和文件 ID，并验证真实路径。拒绝绝对路径、穿越、未登记文件和越界符号链接。入口不提供任意文件读取或自动上传能力。

### iOS 分享扩展

新增 `BridgeShare` Share Extension target、主 App 原生收件箱插件、同名 App Group 权限及嵌入关系。扩展只复制到 App Group 本地目录；用户点击“保存”后打开主 App 选择目标，不借扩展强行唤起主 App，也不向 App Group 复制长期凭据。

需要在完整 Xcode 中为主 App 和 BridgeShare 选择同一 Team，给二者配置同一个有效的 `BRIDGE_SHARE_APP_GROUP`（源码示例 `group.dev.feishu.codex.bridge`，实际以账号可用标识为准）。缺少有效配置时展示原因，其他业务入口继续可用。源码、工程和语法检查不能代替 iOS 签名编译或分享面板真机验收。

## 2. 原生通知与待处理中心

- 增加官方 `@capacitor/local-notifications`，新增独立 `/mobile-inbox`，复用 Workbench 的真实待办/通知和原 run 响应接口。不合并 Task Desk、Direct、AAMP、History 的执行状态机，不接管其他 CLI 的交互审批。
- App 包括 Tmux 页面在内，前台读取工作台新事件；浏览器原有行为保持。不会恢复 Tmux Session 列表定时轮询。
- “系统设置 → 本机原生通知与恢复”按当前服务器/设备保存开关和类别。只在用户主动启用时申请权限，拒绝后站内待办仍可用；后台即时推送未配置的边界在页面中明确显示。
- 启用时读取当前服务端通知 ID 作为基线，不用手机/服务器时钟比较，避免历史消息弹窗风暴；记录本机已处理 ID，重复读取和重启不重复提醒。禁用类别不影响站内记录。
- 锁屏文案只提示事件类别，不写任务正文或代码。通知携带服务器、设备作用域和安全页面路由，不携带 Bearer、Action Token、配对码，也不附带可直接执行的批准/发送动作。
- 不申请精确闹钟能力。新增依赖的 Kotlin 编译器统一为现有 Filesystem/FileTransfer/Barcode Scanner 使用的 2.2.20，避免模块各自引入不同工具链。

## 3. 安全打开与恢复

- Android/iOS 登记 `bridgecodex://connect` 和 `bridgecodex://open`。App API 处理冷/热启动，原生通知点击复用同一导航队列。
- open 链接格式：`bridgecodex://open?server=<编码后的服务器 origin>&path=<编码后的页面路径>`。只接受已知只读导航页面及参数，拒绝 API 路径、外部跳转、凭据参数、模糊重复参数和路径穿越。
- 同环境在完成鉴权后打开；不同环境必须用户确认、验证已有授权及可达性后切换，缺少授权走连接设置。失败保留原环境；不从链接自动提交任务、发送输入或响应审批。
- 通知额外校验设备作用域，旧授权/旧安装实例的通知不能误开到新授权同名任务。原请求失效仍由后端拒绝，通知不替代状态校验。
- 未完成的页面打开请求可在本机跨重启保留，已消费后移除；不持久化原始 URL 或配对码。配对必须用户明确确认，配对码只留在内存；冷启动去重只保存 URL 摘要到 session 存储。
- 工作页按服务器和设备恢复，可在设置关闭。显式通知、链接和任务草稿优先于恢复；不恢复提交、审批或终端按键，不自动重放网络结果不确定的操作。

## 5. 使用入口

1. 手动覆盖安装本次 Android 调试包，不先卸载或清空数据；尚带旧数值校验错误的 App 不能依靠自身更新校验器完成这次修复。
2. 从系统相册、浏览器或文件管理器分享至 Bridge。复制完成后打开“系统管理 → 分享收件箱”（位于“App 连接”下方），选择当前环境的目标，只追加草稿，检查后在原页面发送/提交。
3. 打开“系统设置 → 本机原生通知与恢复”，主动授权并启用；完成、失败、待处理可以分别设置。保留原站内通知与 Web 兼容偏好。
4. “系统管理 → 待处理”（位于“App 连接”下方）可独立查看和响应已有真实请求。“待处理”和“分享收件箱”不占一级导航，页面路由保持不变。通知点击同环境可直达，跨环境需确认；旧授权作用域会被拦截，不自动执行任何链接动作。

原生能力依据：[Capacitor Local Notifications](https://capacitorjs.com/docs/apis/local-notifications)、[Capacitor Deep Links](https://capacitorjs.com/docs/guides/deep-links)。本批登记的是自定义 scheme；HTTPS App/Universal Links 的域名验证及后台推送属于后续配置范围。
