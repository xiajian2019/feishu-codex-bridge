# 浏览器配对诊断与扫码

## 授权未到期仍要求配对

服务器会话的 `expires_at` 与浏览器 Cookie 的到期时间是两份状态。首次配对默认写入 30 天的 Cookie；管理员为另一台设备延期时，仅刷新管理员浏览器的 Cookie，不能直接修改目标手机已保存的 Cookie。目标手机可能在服务器授权仍有效时失去本地凭据。

现在 `/api/auth/status` 和通过 `requireAuthorization()` 的有效请求会按该会话在数据库中的到期时间刷新调用设备自己的 Cookie。前端在回到页面、恢复网络以及可见页面的定时检查中同步授权；访问本身不会延长数据库授权。Bearer 请求不写浏览器 Cookie，失效或撤销的会话不续发 Cookie。已经丢失的 Cookie 仍需重新配对。

配对页区分：没有携带凭据、凭据格式无效、会话不存在、授权到期、授权撤销。没有 Cookie 时，服务器无法断言浏览器具体为何未发送它。页面保留最近成功访问时间、服务器授权到期、服务标识及最多 20 次状态变化；浏览器清理存储、切换地址或首次启用诊断前的情况无法完整回溯。

“复制诊断信息”包含当前地址 origin、浏览器能力、服务器时间、上述状态和最近识别的分辨率/尝试次数。不会保存或导出会话 token、配对码、二维码照片、文件名、完整地址查询参数或 fragment。

## 扫码入口

- 按钮统一为“扫码配对”。HTTPS 且浏览器允许摄像头接口时，使用本地打包的 `qr-scanner` 连续扫描，成功后直接在当前页面配对。
- HTTP 或缺少摄像头接口时，使用带 `capture="environment"` 的图片选择器调用手机拍照；具体相机/文件选择界面由浏览器决定。
- 连续扫码可显式切换“改用拍照识别”；先释放视频轨道，再打开拍照入口。取消、隐藏页面和离开页面都会结束扫码摄像头。
- “选择二维码图片”与输入配对链接/配对码始终保留。图片在浏览器本地识别，先保留较高分辨率，再用不同尺寸重试，兼容反色二维码；不会上传照片。
- 识别到配对链接后只提取一次性配对码，仍向当前 origin 提交；拒绝其他 hostname 的二维码，允许同一主机的 CLI/开发服务端口不同。
- 实时摄像头访问遵循浏览器安全上下文限制，组件不能绕过 HTTP 限制。参考 [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) 与 [qr-scanner](https://github.com/nimiq/qr-scanner)。

## 验证与开发服务隔离

配对回归测试位于 `tests/pairing-diagnostics.test.ts`，使用内存数据库和随机本机端口，覆盖异设备延期后的 Cookie 同步、撤销/过期、状态历史脱敏、HTTP/HTTPS 扫码选择以及正常/反色二维码解码。前后端类型检查和 Web 构建另行执行。

隔离 Chromium 曾用可控视频帧验证连续扫描自动配对、离开后轨道结束、Cookie 丢失后的历史诊断与 390 px 宽度。该证据不代表华为摄像头、受信任 HTTPS、系统拍照界面或实际拍摄照片已完成验收；最新自适应入口的真机行为仍需检查。

浏览器测试必须使用独立端口、临时数据库和独立浏览器 context；不修改正在使用的设备 Cookie、默认页面、系统代理或正式 tmux。测试构建输出到临时目录，避免替换实际服务正在使用的产物；结束时只关闭本次创建的 context、服务和视频轨道。必要时改用命令行测试，不在用户使用 5173 时继续启动浏览器验收。

源码 checkout 的 Vite HMR 与 API `--watch` 是另一项影响来源：修改后端源码可触发 API 短暂重载；新增依赖可触发 Vite 重新优化并刷新页面。独立测试端口不能隔离这些源码监视行为。应将改动成批应用，测试阶段不额外改动依赖或开发服务配置；检查 `web.log` 的依赖优化/代理错误与 `api.log` 的启动时间来区分原因。


## 设备授权管理与共享库环境

列表的一条记录表示一次浏览器或 App 授权，并不等于一台实体设备。默认按当前授权、最近使用排序；名称备注保留用户命名，浏览器/系统/型号只作辨认提示。完整 UA、精确时间和授权编号放在折叠详情；同型号提示不自动合并或撤销凭据。

管理页可搜索名称、浏览器、型号、IP、授权编号和已知入口端口；提供有效/历史记录、同型号多份、七天未使用及七天内到期筛选。批量全选排除当前授权，撤销前列出具体目标；单独撤销当前授权时明确提示退出。批量操作复用既有逐条鉴权撤销 API，部分失败会保留未完成项并反馈结果，不宣称原子批量成功。历史保留已过期、已撤销的记录，不删除数据库中的会话引用。

`web_auth_sessions` 增加 `client_type`、`last_access_origin`、`last_access_origin_at`，通过增量迁移保留现有 token、备注和到期时间。App 配对使用 App 类型，旧记录在有效请求时补齐显示元数据；类型与 UA 标记不参与授权决策。

最近访问环境以成功鉴权请求的公开 origin 为准，列表展示实际端口，详情展示完整 origin。开发 Vite 的 `/api` 代理覆盖 `X-Bridge-Public-Origin`，从浏览器实际访问的 Host/协议生成该显示字段；API 仅从 loopback 代理接收此元数据，且它不参与 Origin/Action Token 验证。端口切换不受一分钟 last-seen 写入节流影响；数据不含页面路径、查询参数或配对 fragment。

共用数据库时，旧版服务仍可读写原有字段，但不能补录它不支持的访问入口。如果最近访问时间新于入口记录时间，页面显示“访问入口未记录”，避免把早先另一个端口误当成最近环境。已安装的旧二进制需要单独升级并访问后，才能完整记录该服务端口；仅修改源码不等于升级安装版。后台鉴权轮询也算访问，当前字段不是用户前台页面的浏览历史。

本轮验证使用临时数据库、旧 schema 迁移 fixture、HTTP/API 与服务端 React 渲染，Web 构建输出到临时目录；不启动浏览器自动化，也不更改用户实际设备的名称或撤销状态。真实手机的列表布局及操作仍须单独验收。
