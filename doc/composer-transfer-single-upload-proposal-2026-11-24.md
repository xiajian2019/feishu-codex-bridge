# 手机传入 Composer 附件的单次上传方案

状态：当前 checkout 已按方案实现，尚未部署或真机验收。手机发送到 Bridge 的文件在加入 Composer 后可复用，避免接收端下载完整文件再上传一次；普通附件、“＋”、草稿和旧客户端路径继续保留。

## 改造前的数据流和边界

1. 手机分块上传至 Bridge 的 `composer-transfers` 临时目录，目标 Session 和设备保存在 SQLite 中。
2. 接收弹框逐个下载文件，构造浏览器 `File` 并加入草稿；草稿附件可能进入接收端 IndexedDB。
3. 草稿加入并确认后，服务端安排清理临时文件；正式发送时，附件适配器将浏览器 `File` 再次传回 Bridge，生成正式附件路径。

因此并非所有副本都会长期同时存在，但大文件仍会经过 Bridge → 接收端 → Bridge，接收端也可能保存完整副本。原手机文件不在 Bridge 的清理范围内。旧客户端或旧后端仍使用此兼容路径。

## 建议的数据流

1. 保持手机端现有分块上传和校验。文件完成前仍属于接收码作用域；关闭弹框时终止本次接收并清理未加入草稿的临时文件。
2. 新增有版本或能力标记的“加入草稿”接口。接收端确认加入时，服务端校验传输已完成，给每个文件生成不透明附件 ID，并把文件提升到现有正式附件目录。相同文件系统优先使用独占硬链接加删除临时链接或安全重命名，避免复制文件内容；跨文件系统时才流式复制、校验并清理旧文件。
3. 提升完成后返回文件名、类型、大小和附件 ID。Composer 保存服务端附件引用，而不是下载完整文件构造 `File`；需要预览时通过受鉴权接口按需读取。macOS 使用 `sips` 生成有界缩略图；暂不支持缩略图的环境显示占位，点击后仍可读取完整图片。
4. 正式发送时，由服务端按附件 ID 和当前作用域重新校验，解析到受控目录中的正式路径，再复用现有 Composer 提交格式。普通本地附件继续使用现有上传接口；旧客户端或不支持新能力的后端继续走现有链路。

## 实施要点

- **可靠提升**：SQLite 为提升操作记录稳定的幂等键、源文件、目标文件、状态和引用。文件系统操作与数据库事务不是同一个事务，须有可重放的中间状态；断电、网络响应丢失或重复点击后可恢复，不能重复加入、覆盖文件或删除唯一副本。多文件中途失败时保留可重试状态，并按明确的全部提交或逐项提交契约处理。
- **作用域和路径**：附件引用绑定 Bridge 安装实例、授权设备、目标 Session 的持久记录及 `createdAt`。预览、恢复、删除和发送时都重新鉴权；客户端不能指定任意服务端路径。最终文件名与 `attachmentStorageName`、图片查看及 `submissionFingerprint` 的现有路径约束兼容，校验真实路径、常规文件和符号链接边界。
- **预览安全**：图片缩略图和原图均走鉴权；SVG、HTML 等可携带活动内容的文件不能作为同源可执行页面打开。可用安全图片上下文或隔离预览，对普通文件使用下载方式，并保留已有文件预览能力。
- **草稿与附件适配器**：当前 `@assistant-ui` 支持加入无 `File` 的 `CreateAttachment`，但当前草稿保存代码过滤 `status === "complete"` 的附件，预览也依赖 `attachment.file`。需明确区分本地文件和服务端引用，修改 UI、草稿序列化与恢复；禁止用空 `File` 冒充完整文件。保留原有草稿内容，导入只追加。
- **生命周期**：未确认的接收继续使用短期接收码；已加入的文件转为草稿引用，刷新或服务重启不能因接收码过期而丢失。草稿移除、清空、设备撤权和过期均释放各自引用；发送成功后按现有 Session 历史和 Codex 读取需求保留，不能立即删除。发送前解析过的文件保守标记为保留，因为失败也可能代表投递状态不确定；未发送的草稿引用在移除或过期后经过宽限期清理，并由恢复任务处理未完成提升。
- **离线与兼容**：本地附件保留现有离线草稿能力；服务端引用在 Bridge 不可达时应保留草稿和引用，明确显示暂不可预览/发送，不能静默删除。小缩略图缓存可改善离线体验，但不能声称完整原图始终可离线使用。不要引入新的应用层总文件大小上限。
- **去重范围**：首版只复用同一次传输的实体文件，不按哈希跨用户或设备全局合并；SHA-256 用于完整性与恢复核对，避免跨作用域信息泄露和误删共享文件。
- **已验证边界**：隔离 HTTP 测试覆盖超过 100 MiB 文件、同盘 inode 复用、缩略图和作用域校验；跨文件系统及不支持硬链接的回退通过注入式测试。浏览器 fixture 覆盖旧版回退、草稿恢复、热更新、作用域切换和失败重试；使用隔离数据库和假 Session 的浏览器与真实 HTTP 服务联调也验证了大文件只上传一次。尚未在真实手机和真实弱网下验收。

## 验收建议

- 使用隔离 DB、假 Session 和 100 MiB 以上文件，核对哈希、网络请求和磁盘文件：手机仅上传一次，加入与发送不再回传完整文件；同文件系统下确认提升不产生第二份物理内容。
- 验证旧/新客户端与后端组合、本地附件混合、多个文件、原草稿追加、预览、发送失败/结果不确定、刷新/重启恢复、重复请求及响应丢失。
- 验证取消中的分片、到期清理、设备撤权、不同设备/Session 的越权引用、路径穿越及符号链接。浏览器 fixture、真实 iOS/Android 设备和弱网/大文件证据分别记录。
