# Happier 借鉴功能实施清单

用户确认：优先任务面板与 Codex 历史详情；Tmux Git 意见交给原 Session 的命令行 Codex，先写入草稿、确认后发送。主代理负责契约、分工、审查、集成与验收，子代理实现互不冲突的切片。保留当前 checkout 已有改动；不自动提交、发布、部署或创建 worktree。

## 范围与顺序

- [x] 1. 待处理中心与结构化问题/审批：任务面板聚合真实请求，History 原生事件驱动卡片；过期请求不可操作，审批结果回到原 run。仅显式开启 History 交互审批时使用原生双向协议，原 SDK 默认行为不变。
- [x] 2. 跟进队列：任务与 History 可排队、编辑、删除、排序，只有原执行链路空闲才派发；区分保存、发送、执行与结果未知，不自动重放不确定提交。加入队列即授权空闲自动发送，AAMP 仍只读。
- [x] 3. 通知首阶段：完成、失败、等待用户事件去重，支持偏好、深链接和浏览器允许的系统通知；全局轮询不依赖停留任务面板。飞书主动推送未接入，见下方限制。
- [x] 4. 连接恢复：History/任务保留原查询恢复，新增工作台显示离线与重试；Tmux ping/pong、重连与原有滚动契约兼容，不在重连时重放消息。
- [x] 5. Tmux Git 评论（按后续反馈修订）：路径、行号、片段随普通文本加入原 Session 的 composer 草稿，保留已有草稿、不自动发送；不检查 Codex/pane/PID，不生成隐藏投递标记。用户点击发送时走原有普通 composer 链路，不另起 SDK。移动端文件/Diff 单视图切换、意见按需抽屉，不再常驻挤占阅读区。
- [x] 6. 会话组织：Task/History 置顶、标签、已读和保留关注独立于执行状态，按原 task/home/thread 身份持久化。列表筛选/置顶明确只作用当前已加载页，不冒充全量检索。
- [x] 7. 模板与同配置任务草稿：变量填写后插入草稿；Task 复制项目、mode 和描述，不复制附件；History 只在 cwd 精确匹配已登记项目时转入空任务草稿，明确不继承 Home/model。完整的 History 原配置新会话仍不支持。
- [x] 8. History 导航与转发：按轮次跳转、关键消息收藏、选中消息转入目标会话草稿，确认后发送。收藏按本地安装/设备隔离。
- [x] 9. History 分叉：通过官方 thread/fork，并可传 lastTurnId；能力不足返回真实错误，不模拟复制，不对原会话隐式 rollback。
- [x] 10. 自动化首阶段：系统管理页面，IANA 时区/固定分钟周期、暂停、幂等立即运行、独立提交/执行记录；复用已登记项目和原任务/History 入口，持久化领取，不重派不确定时点。暂不提供 cron 表达式。
- [ ] 11. 执行机器：系统管理页面区分浏览器配对设备与执行主机；真实远程执行/迁移必须有受认证的主机入口及可用协议，不能把本地 tmux 或注册一个 URL 描述成已完成跨机迁移。

## 并行职责

- 主代理：共享数据库集成、HTTP 鉴权/路由、队列派发、契约复核、安全竞态与自动化执行关联修正、整体验证。
- 子代理 A：Tmux Git 评论与安全投递，限 Tmux/Git 页面和相应后端/测试。
- 子代理 B：History 导航、组织、模板与转发 UI，复用主代理提供的 workbench API；不改公共 DB/HTTP 路由。
- 子代理 C：Workbench 附加元数据、队列、通知、模板与调度定义的 SQLite store 和测试，不修改原任务状态机。
- 子代理 D：显式 History 原生交互、审批/问题、fork/steer、协议及生命周期测试。
- 子代理 E：任务面板/详情、通知偏好与全局通知、自动化和执行机器管理页面。
- 本次可用代理模型没有 `gpt-5.6-luna`，已说明并采用 `gpt-6-luna` / `max`；主代理独立审查和集成，不将子代理自报测试当成最终验收。

## 已知前置条件

当前 SDK 的 exec JSON 流不提供双向用户审批响应；交互卡片需要官方 app-server 双向协议。现有 read-only app-server 客户端继续只读，交互能力须显式启用并由 History 所属 run 持有。远程主机及飞书主动通知只在实际已配置且用户授权的目标上验收。

## 实现边界与后续前置条件

### Git 审阅交互修订

用户截图显示顶部摘要和常驻意见面板把文件列表与 Diff 压缩成窄条。现已压缩页头、将路径/HEAD 与截断说明折叠，手机端“文件 / Diff”各占完整阅读区域；行级意见改为按需抽屉，桌面仍保留左右分栏。

之前把草稿追加错误地绑定到前台 Codex 的 PID/pane，并在加入草稿时调用终端投递预检。该 UI 流程已移除；保存意见 → 打开意见 → 加入输入框草稿，无二次确认、无进程校验、无自动发送。旧 review API/特殊 WS 校验仍仅作为兼容后端接口保留，当前页面不调用它们，也不发送 `review` 元数据。旧草稿的隐藏标记会在普通发送前去除，不再要求旧进程凭据。

隔离浏览器实测：390×844 时文件列表与 Diff 可分别获得约 604px 高度，无页面横向溢出；手机独立页与桌面弹窗均可将意见追加到已有 composer 草稿。模拟终端没有 Codex，加入草稿时进程检查请求数与发送数均为 0；仅手动点击发送后产生一次普通 `submit`，无 `review` 元数据。实际手机/软键盘仍单独验收。

本次修订回归：`bun test` **371 passed / 0 failed**（68 files，2077 assertions）；前后端类型检查和 Web 构建通过。320×568 小屏文件区域仍有约 328px 高度，390×844 行号触控高度为 32px；1280×900 桌面弹窗保留约 553px 的左右阅读区。另修复了桌面弹窗在同一路由跳回已挂载 composer 时没有消费新草稿的问题。

后续多行交互按用户再次确认调整为：点击行号只选择/高亮，不直接弹窗，也不需要预先开启“多选”模式；点击同侧起止行形成连续范围，再点击顶部“意见”填写一条范围意见。可继续点击调整结束行，或清除选择；无选区时“意见”打开已保存列表。单行/多行意见均保留原 Session 草稿追加、不自动发送的约定。范围包含准确起止行和全部所选代码，持久化兼容既有单行记录；不跨未展示的 diff 缺口或文件/新旧侧拼接，单条最多 200 行、片段最多 16 KiB。关闭按钮固定 36×36、零 padding、不可 flex 拉伸，避免被全局按钮最小高度撑成椭圆。

### 其他边界

- 页面：`/` 任务面板、`/tasks/:source/:taskId`、`/codex-history/:homeId/:threadId`、现有 Tmux Git Changes，以及新增 `/system-management/automations`、`/system-management/machines`；通知偏好在系统设置。
- History 交互审批需要用户在下一轮设置显式开启。普通发送和队列保留 SDK 续聊；不能接管其他 CLI/App 正在运行的审批。steer 也只接受本服务当前持有的原生 run。MCP elicitation 仅显示 schema/拒绝，尚不提供通用 schema 表单授权。
- 自动化是 Bridge 进程存活时执行的固定间隔调度，不是操作系统后台调度服务；时区用于展示，不宣称是日历时刻或 DST/cron 调度。已接受提交不等于 Codex 已执行完成。
- 远程机器当前只有本地主机能力与远端地址登记。实际跨机执行/会话迁移缺少目标主机、认证方式、远端 agent/协议和路径映射；没有这些条件，不能标记第 11 项完成，也不能把本地 tmux 当远程主机。
- 飞书主动通知尚未接入新的工作台通知；需要明确目标与授权/去重策略，不能盲目复用未知聊天或额外启动另一个 Bot 消费者。浏览器关闭、系统通知权限不允许时，不保证系统通知送达。
- 未提交、推送、发布或重启真实服务。真实 Codex、真实 tmux、真机触摸操作及远端主机不属于本轮隔离验收结果。
- 原生协议依据：[OpenAI Codex App Server](https://learn.chatgpt.com/docs/app-server)。CLI 生成型只用于核对协议，未解析 Codex 自有数据库或历史 JSONL。
